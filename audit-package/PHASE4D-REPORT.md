Date: 2026-11-23. Scope: factory only (builder, templates, pipeline, validator, docs). No new video, no voice, no render of a new video, no publication. All four 4C follow-ups are resolved; the regression proves the changes left the gate's measured values on existing videos unchanged.

## 1. The four corrections

### 1.1 HyperFrames check-cache trap — fixed in code

- **Defect:** `npx hyperframes check` returns a cached report with no "report saved to" line when nothing changed, and `rendering/build_video.py` judged the check only by that line → false FAILED. Manual workaround (delete `videos/<slug>/.hyperframes/cache/check.json` before the run) is removed as a procedure.
- **Fix (`rendering/build_video.py`):** the check block is now the module-level function `run_hyperframes_check(out_dir) -> int` (extracted verbatim, directly testable; `main()` delegates to it). Two guards: (1) cache invalidation before the run — deletes `videos/<slug>/.hyperframes/cache/check.json` (`FileNotFoundError` tolerated), forcing a real re-check; (2) freshness verification after the run — the saved report's mtime must be ≥ the timestamp recorded just before invoking the check, otherwise the build fails with a stale-report message and never silently accepts a cached report. Also fixed a latent path bug: a relative saved-report path is resolved against `PROJECT_DIR` instead of the process cwd. `import time` added; the rest of the block (exit-code note, stdout-fragment warning, `ok` + `errorCount` verdict) is unchanged.
- **Proof (real execution):** the trap was reproduced live on `videos/factory-test-2` (23 Nov 2026 ~21:15 UTC): a warm-cache re-run returns the full cached report on stdout (`ok:true`, 0 errors), empty stderr, no "report saved to" line in either stream — the old code would have read it as FAILED. A proof driver importing the real `build_video.run_hyperframes_check` passed all tests: (1) seeded bogus stale cache (`ok:false`, 99 errors, dated 2020-01-01) → returned 0, bogus file gone, fresh cache written; (2) missing cache file → returned 0, fresh check ok; (3) stubbed subprocess returning a stale artifact (mtime 2020) → refused with the stale-report message, returned 1. `py_compile` passes. The seeded test folder was restored byte-identical afterwards (SHA-256 verified); no existing file was deleted. No full build was run (that would generate voice/video, out of scope); the proof exercised the real check function.
- **Limits:** the first proof run failed on the pre-existing Chrome-cache permission quirk (`~/.cache` group-writable again; fixed with the documented `chmod go-w ~/.cache ~`; reverts between sessions). The stdout `_meta.checkedAt` is not per-run (identical across two different runs) and must never be used as freshness evidence. The staleness guard's normal path never triggers while cache deletion works; it exists as a backstop and was proven only via the stubbed-subprocess test, not a live stale artifact.
